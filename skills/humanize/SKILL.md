# humanize

Each file beside this one records the rules agents most often get wrong on one topic. Before you write or review something, read the files for every topic it touches, and follow them over local habit: where an older file's own style disagrees, the convention wins.

| When you | Read |
|---|---|
| write, change or review C++ | [cpp-coding-conventions.md](cpp-coding-conventions.md) |
| write, change or review Python | [python-coding-conventions.md](python-coding-conventions.md) |
| write, change or review Swift | [swift-coding-conventions.md](swift-coding-conventions.md) |
| write, change or review TypeScript | [typescript-coding-conventions.md](typescript-coding-conventions.md) |
| commit, write a commit message, split work into commits or write a pull request | [git-conventions.md](git-conventions.md) |
| write or edit a repository's README | [readme-conventions.md](readme-conventions.md) |
| write or change a web page (HTML, CSS and what it presents) | [web-conventions.md](web-conventions.md) |
| write or edit the prose of a LaTeX document | [latex-conventions.md](latex-conventions.md) |

The language conventions share one style: where a rule has a counterpart in another language, the two read the same, so reading one file's counterpart settles a doubt in another.
